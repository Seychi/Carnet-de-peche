## 2. 🔴 Critiques (à traiter avant d'ouvrir les vannes)

### 2.1 Économie XP falsifiable → intégrité des classements publics compromise
Le travail SQL 098-103 est rigoureux (RLS, search_path, REVOKE/GRANT, k-anon, opt-in serveur : tout ✅). Mais l'économie repose sur des entrées déclaratives non protégées :

- **Boucle create/delete** (vérifié dans `098_xp_progress.sql:126-179`) : `award_catch_xp` calcule rendements décroissants (`v_same_day`), nouvelle espèce (`v_prior_species`) et record sur les prises **encore présentes** dans `catches`. La suppression ne révoque pas l'XP (décision documentée 098:32-33). Donc : loguer → supprimer → reloguer = **+10 (prise) et même +50 (nouvelle espèce) à l'infini**, carnet propre. La mitigation revendiquée dans le commentaire (« l'unique + rendements décroissants évitent le farm ») est fausse sous suppression.
- **Zéro rate-limit sur `createCatch`/`bulkCreateCatches`** (`lib/catches/actions.ts:103, 547`) alors que feed/spots/login/co-pêchage en ont un.
- **« Photo-vérifiée » sans photo** (vérifié `lib/catches/actions.ts:144-163`) : `photo_verified_at` est posé si `is_measured` + longueur + `reference_object` (texte libre). **`photo_path` n'est jamais exigé.** Or le PB +30, le +15 « mesurée » et la métrique « Plus grosse » des classements (102:30-31) vendent cette donnée comme « standard record anti-farm ». Un rang #1 « plus grosse prise vérifiée » est déclarable sans photo.
- **Anti-datage incohérent** : l'XP filtre sur `created_at` (anti-antidatage ✅) mais streaks (099:79-84) et défis (100:126-151) comptent sur `caught_at` **déclaratif** → 52 prises antidatées = série de 52 semaines + badges + XP hebdo, classés publiquement.

**Pack de remédiation proposé (≈1 sprint, « Intégrité »)** :
1. Recalculer les compteurs anti-farm sur `xp_events` (append-only) et non sur `catches` — OU révoquer l'XP au DELETE (trigger miroir).
2. Rate-limit prises : ex. 20/24 h + burst 5/h (généreux pour un vrai pêcheur, bloquant pour un script).
3. `photo_path` obligatoire pour poser `photo_verified_at` (le flux mobile caméra+IA le remplira naturellement ensuite).
4. Aligner streaks/défis sur `created_at` (ou borner `caught_at` à ±48 h de `created_at` pour tout ce qui crédite XP/badges).
5. Plafond journalier sur `measured`/`released` comme sur `catch`.
