## 4. Findings priorisés

### 🔴 C1 — Performance `/carte` (le plus gros caillou technique)
- **Constat** : Lighthouse **mobile ~35 / TBT ~3 920 ms** (mesuré sprint 28), long task d'init MapLibre ~1,5 s = 100 % du TBT. Le lazy-load (sprint 16) ne suffit pas (le coût = le *mount* MapLibre).
- **Pourquoi ça compte avant le mobile** : la carte est la vitrine du produit ET la page la plus lourde. Notre concurrent le plus proche (**Fishing Grid**) a des apps natives fluides ; la perf perçue est leur dernier avantage. Une app native bâtie sur une carte lente hérite du problème.
- **Repro live** : la carte se charge et fonctionne (gating OK, 0 erreur console), mais le mount est visiblement lourd.
- **Reco** : exécuter le **sprint « Carte instantanée »** (planifié sprint 33, jamais fait) : carte interactive différée, skeleton, chargement progressif des spots. **Cible : Lighthouse mobile ≥ 70 / TBT < 600 ms**, mesurée en prod.

### 🔴 C2 — Réservoir vide → le moat est invisible (le vrai sujet)
- **Constat (compté en base le 2026-06-26)** : **19 prises** dont **6 publiques**, **1 post** (fil 06), **17 profils** (12 onboardés), **0 code d'invitation**, **beta non lancée**.
- **Conséquence** : le scoring perso (« le carnet qui parle ») est **construit mais ne peut rien dire** sans données ; un visiteur SEO atterrit sur une carte/fil quasi vides → rebond. Tous les audits notent « time-to-value à froid : 3/10 ».
- **Ce n'est pas un bug, c'est LA décision de lancement.** Reco : trancher (a) seed honnête oui/non, (b) vague beta « fondateurs » (l'infra `invite_codes` est prête, `INVITE_ONLY` off), (c) objectif chiffré de prises/départements avant ouverture large. **À décider par John + César.**

### 🟠 M1 — Log d'une prise par nom de ville **cassé** (UX cœur)
- **Repro live** : champ « Ville ou lieu (ex : Camaret-sur-Mer) » → je tape « Camaret » (vraies frappes clavier) → **aucune autocomplétion**, et à la soumission : **« Position requise. Utilise le GPS ou saisis les coordonnées. »** Le champ texte **ne géocode jamais** la ville saisie.
- **Impact** : sur **desktop** (ou si la géoloc est refusée), et pour **loguer une ancienne prise** depuis chez soi, l'utilisateur est **bloqué** sauf à connaître ses coordonnées GPS (saisie manuelle lat/long). Or « importe tes prises » est le nudge central de l'onboarding et du cockpit. La prise ne s'est enregistrée **que** via coordonnées manuelles.
- **Reco** : brancher un géocodage sur le champ ville (ex. API **BAN adresse.data.gouv.fr**, gratuite, FR) avec liste de suggestions → coords. À défaut, requalifier le placeholder et faire du GPS/manuel le chemin explicite (mais le géocodage est clairement attendu vu le placeholder).

### 🟠 M2 — Heures de soleil fausses sur le cockpit `/home`
- **Repro live** : utilisateur Brest/Finistère → bandeau « ☀ Soleil **08:19–00:23** ». Or à Brest le 26 juin : lever **~06:17**, coucher **~22:14**. Un coucher à **00:23** est aberrant.
- **Impact** : donnée **visiblement fausse** sur le tableau de bord principal — ça abîme le positionnement « instrument de précision marine ». À vérifier : est-ce que ce calcul lever/coucher alimente aussi la composante **Astro** du score générique (risque de biais du score) ?
- **Reco** : corriger le parsing/TZ des champs `sunrise/sunset` (probablement Open-Meteo daily + offset Europe/Paris), ajouter un test de non-régression, et vérifier l'impact sur le scoring astro.

### 🟠 M3 — En-têtes de sécurité HTTP absents
- **Constat (revue code)** : `next.config.ts` n'a **ni** `Content-Security-Policy`, **ni** `X-Frame-Options`/`frame-ancestors` (anti-clickjacking), **ni** HSTS, **ni** `X-Content-Type-Options: nosniff`, **ni** `Referrer-Policy`.
- **Impact** : pour une app avec JSON-LD injecté et un tunnel Stripe, c'est le principal durcissement manquant avant une ouverture publique.
- **Reco** : ajouter un bloc `headers()` (au minimum `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, HSTS ; **CSP en `report-only` d'abord** pour ne pas casser MapLibre/Stripe/PostHog).

### 🟠 M4 — `CLAUDE.md` périmé (cf. §2). Resync = ~1 h, évite des briefs faux.

- **m6 — Hygiène DB (advisors)** : 2 FK sans index (`invite_codes.created_by`, `outings.spot_id`) → ajouter ; nombreux index inutilisés (surtout schéma `stripe` FDW + quelques public) → revoir après lancement ; `invite_codes` RLS activé **sans policy** (fail-closed, OK mais à documenter) ; 3 extensions en schéma `public` (postgis/citext/pg_trgm, généralement laissé). **Rappels assumés (ne pas re-signaler comme TODO)** : HIBP off (Pro-only), `security_definer` sur `catches_for_viewer`/`spots_for_viewer` (documenté migration 047), `spatial_ref_sys` RLS (système PostGIS).
